# API reference: NanoEX Web

Interactive docs are generated by FastAPI while the backend runs:
- Swagger UI: <http://localhost:8000/docs>
- ReDoc: <http://localhost:8000/redoc>
- OpenAPI JSON: <http://localhost:8000/openapi.json>

Base path: `/api/v1`. All bodies are JSON. Money values are in rupees with 2 decimals.

## Response envelope

Every REST response has the same shape:

```json
{ "success": true, "data": { ... }, "error": null, "meta": { "page": 1, "size": 25, "total": 140 } }
```

On error:

```json
{ "success": false, "data": null,
  "error": { "code": "RISK_LIMIT_EXCEEDED", "message": "Order value exceeds your max order value", "details": { ... } },
  "meta": null }
```

Common error codes: `VALIDATION_ERROR` (422), `AUTHENTICATION_FAILED` / `INVALID_CREDENTIALS` (401), `ACCOUNT_DISABLED` (403), `PERMISSION_DENIED` (403), `NOT_FOUND` (404), `EMAIL_TAKEN` (409), `NOT_FLAT` (409), `NO_OPPORTUNITY` (409), `RISK_LIMIT_EXCEEDED` (400), `INSUFFICIENT_FUNDS` (400), `TOPUP_LIMIT` (422), `RATE_LIMITED` (429), `MARKET_UNAVAILABLE` (503). Orders that fail a risk check are also saved with status `REJECTED` and the reason, so they show in your order history.

## Authentication

1. `POST /auth/login` returns `data.access_token` and sets the `nanoex_refresh` cookie (httpOnly, path `/api/v1/auth`).
2. Send `Authorization: Bearer <access_token>` on every other call. It expires after 15 minutes.
3. When a call returns 401, `POST /auth/refresh` (the cookie goes automatically) to get a new access token. The cookie rotates every time.

## Endpoints

🔓 public · 🔑 logged-in user · 🛡 admin only

| Method | Path | | Description |
|---|---|---|---|
| POST | `/auth/register` | 🔓 | Create account `{email, password, full_name}`; wallet of ₹5,00,000 is created. Rate limited |

## WebSockets

Both need the access token: `ws://host/ws/market?token=<access_token>`.

### `/ws/market`
Server → client messages:
```json
{ "type": "tick", "data": [ { "symbol": "TCS", "exchange": "NSE", "bid": 4100.5, "ask": 4100.7, "last": 4100.6, "volume": 478955, "timestamp": 1761587905.2 }, ... ] }
{ "type": "depth", "data": { "symbol": "TCS", "exchange": "NSE", "bids": [{ "price": 4100.5, "quantity": 120, "orders": 3 }], "asks": [ ... ] } }
{ "type": "arb_opportunity", "data": { ... } }
```
Client → server, to choose which book's depth to receive:
```json
{ "action": "depth", "symbol": "TCS", "exchange": "BSE" }
```

### `/ws/user`
Only your own events: `order_update`, `trade`, `arb_result`, `wallet`.

## Example session (curl)

```bash
B=http://localhost:8000/api/v1
curl -s -c jar -X POST $B/auth/register -H 'content-type: application/json' \
  -d '{"email":"me@example.com","password":"secret123","full_name":"Me"}'
T=$(curl -s -c jar -X POST $B/auth/login -H 'content-type: application/json' \
  -d '{"email":"me@example.com","password":"secret123"}' | python -c "import sys,json;print(json.load(sys.stdin)['data']['access_token'])")

curl -s -X POST $B/orders -H "authorization: Bearer $T" -H 'content-type: application/json' \
  -d '{"symbol":"TCS","exchange":"NSE","side":"BUY","order_type":"MARKET","quantity":5}'

curl -s $B/arbitrage/spreads -H "authorization: Bearer $T"
curl -s -X POST $B/arbitrage/execute -H "authorization: Bearer $T" -H 'content-type: application/json' \
  -d '{"symbol":"INFY","quantity":50}'
curl -s $B/dashboard/profit -H "authorization: Bearer $T"
```
